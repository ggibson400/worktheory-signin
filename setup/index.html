Set up Claude for your practice

Connect Claude to Work Theory, set the rules for when Claude checks with you, and give each client a claude.ai project. From then on, Claude briefs you on the client, saves what it learns, and keeps you in the loop when the client uses Claude without you.

1Connect Claude to Work Theory once

  1. In claude.ai, go to Settings → Connectors (under Customize) and choose Add → Add custom connector.
  2. Name it Work Theory, with this URL:
    https://vykvpabpeumddbrgoxnb.supabase.co/functions/v1/mcp
  3. Choose Connect, sign in with your email address and the staff passcode, and choose Allow.
  4. Open Work Theory in your connectors and set every group under Tool permissions to Always allow, so Claude saves as it goes without stopping to ask. Nothing is ever deleted; the history stays.

2Decide when Claude checks with you once per practice

Your practice's rules name the topics where Claude must check with you before answering a client or doing work for them. When you're in the conversation, Claude just asks you; the rules are for when a client uses Claude alone.

  1. Start a conversation outside any project, with Work Theory switched on in the tools menu.
  2. Send:
    Brief me on my Work Theory practice, then help me set its rules: the topics where Claude must check with me before answering my clients or doing work for them.
  3. Claude suggests rules for your field and saves them once you agree. Change them in any conversation.

3Set up a client's project per client

  1. Create a claude.ai project named after the client.
  2. Copy these instructions into the project's instructions. Claude finds the client by name; you don't need an id.

  3. Start a conversation in the project, check Work Theory is on in the tools menu, and send:
    Check that Work Theory is connected, brief me on this client, and tell me what we should do first.
  4. For a client already in your practice, Claude briefs you. For a new one, it checks with you, adds it, and offers a brain dump: tell it what you know and it saves each fact. You can skip that.

4Invite the client's own person optional

For someone on the client's side who will use Claude with you in the loop: an owner, a team member, the person you coach. They need their own claude.ai account.

  1. In the client's project, send this, with their name and email address in the brackets:
    Fill in the client name in step 3 first.
  2. Claude gives you a passcode for them, shown only once, and the link to their setup page. Send both, the passcode separately if you can (a text, say). If they lose it, invite them again for a new one.

Their setup page: Fill in the client name in step 3 first.

Open their setup page to see what they see.

Building things in Claude Code optional

For work that's code (a website, a tool, a script for a client), use Claude Code, on your computer or on the web at claude.ai/code. It reaches Work Theory through the connector you added in step 1, as you, so the briefing, memories and your rules work the same way.

  1. Sign Claude Code in with the same claude.ai account. On your computer, /mcp lists Work Theory; on the web, check Work Theory is on for the session.
  2. Add this to the CLAUDE.md file at the top of the code's folder (with the client name from step 3 filled in), creating the file if there isn't one. Commit it, so sessions on the web get it too.

  3. Start a session in that folder and send the same first message as in claude.ai. When Claude Code asks to use a Work Theory tool, allow it, so it saves as it goes.

On the web, a session reaches package registries and GitHub only. To let it deploy to a service such as Supabase or Vercel, add the service's domains under the environment's network access (Custom), and store its keys as network secrets, never in the code.

Day to day

Talk to Claude in the client's project as you would to a colleague. A few things it does for you:

  • What's waiting for me? Your clients' questions for you (asks to answer before they act, flags to look at afterwards), and their answers to your questions. Approve, edit or replace each answer; Claude passes yours on in your words.
  • Ask the owner whether they have an email list. If not, help them set one up. Your question reaches the client's Claude in your words, and their answer comes back to you.
  • Save that as a lesson. What worked for one client, with no names, for your other clients.
  • Remember that… Anything you want kept about the client. Claude also saves as it goes and tells you what it saved.

If Claude says Work Theory has been updated: go to Settings → Connectors → Work Theory → ⋯ → Refresh tools list, check the permissions are still Always allow, and start a new chat. Claude's working rules update by themselves; new tools need this.
